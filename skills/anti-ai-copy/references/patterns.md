# 各类文案写法

每一类：公式 → 规则 → 对照 → 边界情况。出处缩写见 `sources.md`（Semi / Ant / Arco / TD / M / Apple / MS / Atl / Polaris / GOV / MC / NNg / Krug / Yifrah / Pod）。

---

## 1. 按钮、菜单项、链接

**公式：** 动词 + 名词。弹窗、卡片等上下文已经说清对象时只用动词。

- 用户点之前就能猜到点完会发生什么（Semi、Polaris）。
- 用强动词开头：新建、添加、删除、移除、保存、发布、导出、重试、查看。不用「点击」「立即」「开始」「一键」「马上」这类虚词开头（NNg《"Get Started" Stops Users》）。
- 2–6 个汉字；英文 1–3 个词，不带冠词（Semi、Atl、Polaris）。
- 同一动作全站只用一个词（Semi、Ant、M）：新建 ≠ 添加（新建是凭空造，添加是把已有的放进来）；删除 ≠ 移除（删除是没了，移除是从当前集合拿出去）。
- 按钮不加标点。打开对话框、需要再输入才执行的按钮，英文可加「…」（NNg）。
- 链接文字写去处，不写「点击这里」「了解更多」单独成链（Semi、Apple、MC）。要用「了解更多」就补对象：「了解计费规则」。
- 按钮文字要和它打开的页面标题一致（Ant、Arco、Krug）：按钮「新建评测集」→ 弹窗标题「新建评测集」。

| ✅ | ❌ |
|---|---|
| 保存 | 保存修改内容（Ant、Arco） |
| 新建项目 | 项目新建（Arco） |
| 申请权限 | 申请（Semi：上下文不够时要补名词） |
| 导出通话记录 | 点击导出 |
| Add payment method | Add a payment method |
| Send | Let's do it!（Apple） |

**边界：** 主次按钮成对时，次按钮用「取消」；不要用「否」「不了」「算了」。「确定」只用于纯信息确认（我知道了 / 好的类），有后果的操作一律用具体动词（Apple、NNg、Atl）。

## 2. 标题（页面、卡片、区块、弹窗）

**公式：** 名词短语（通话记录、版本历史）；任务型标题用动词 + 名词（新建项目、导入录音）。

- 关键词放最前面，用户往往只看前两个词（NNg《First 2 Words》）。
- 不写「这是…」「欢迎来到…」「…页面」「…管理中心」。
- 不加句号、冒号；问句可以用问号（Semi、M、MS）。
- 页面标题 ≤ 12 字；卡片标题一个短语。

| ✅ | ❌ |
|---|---|
| 通话记录 | 这是您的通话记录列表 |
| Online store dashboard | This is your online store dashboard（Polaris） |
| 版本历史 | 智能版本管理中心 |

---

## 3. 表单：标签、占位符、帮助文本、校验

**标签：** 名词，说「这是什么」，不是填写说明（Semi Form）。1–3 个词 / ≤ 8 字，不加冒号（M）。

**占位符：** 只放格式示例或可选提示。占位符一输入就消失，不能代替标签，不能放必须记住的规则（NNg《Placeholders in Form Fields Are Harmful》）。选择器没有默认值时用「请选择」即可；Arco 允许「请输入公司办公地址」这种形式，但不要写成规则（❌「公司办公地址请勿为空」）。

**帮助文本：** 字段下方，只写填错会出事的那一条约束，≤ 20 字。

**校验报错：**

- 空值：用指令，复用标签里的词。「输入手机号」「选择外呼时段」（GOV）。
- 超限：用描述。「名称不超过 30 字」「文件不超过 200 MB」（GOV）。
- 格式：给正确的样子。「手机号为 11 位数字」，不说「格式不正确」「非法输入」「invalid」（GOV、Apple、MS）。
- 失焦后再校验，不要一边输入一边标红（NNg《Hostile Patterns》）。
- 保留用户已填的内容（NNg、GOV）。

| ✅ | ❌ |
|---|---|
| 标签「手机号」+ 占位符「例如 138 0000 0000」 | 标签「请输入您的手机号码」 |
| 密码 8–20 位，含字母和数字 | 密码不符合规则 |
| 请输入数字和字母组合（Ant） | 不能输入字符（Ant） |
| Enter how many hours you work a week（GOV） | This field is required |
| Choose a password with at least 8 characters（Apple） | That password is too short |

## 4. Toast / Message / 通知

**公式：** 名词 + 动词（结果）。成功：「X 已 Y」或「Y 成功」二选一，全站统一。失败：「X 失败」+ 原因或一个操作。

- 一句话，不加句号，不加感叹号，不加「啦 / 哦 / 哟 / ～」（Semi、Arco、M、MC）。
- 成功提示不说「成功地」「恭喜」，频率越高越平淡（Atl）。庆祝只留给少见、费力的完成（Semi 语调「庆祝的」）。
- 失败 Toast 最多带一个操作按钮（「重试」「查看」），不放「知道了」「关闭」这类无意义操作（Semi Toast）。
- 失败说原因：「网络错误，创建失败」好于「创建失败」（Arco）。
- 能撤销的操作用「已删除 · 撤销」Toast，比确认弹窗好（Yifrah、NNg）。

| ✅ | ❌ |
|---|---|
| 版本已保存 | 恭喜您，版本已经成功保存啦！ |
| 提交成功（Arco） | 提交成功了哟～（Arco） |
| Language added（Semi） | New language has been added successfully（Semi） |
| 已复制 | 复制到剪贴板成功！ |
| 网络错误，创建失败 · 重试 | 操作失败 |

## 5. 确认弹窗

**什么时候要：** 只给不可撤销、代价大、影响别人的操作（NNg《Confirmation Dialogs》）。高频可撤销的操作不弹窗，改成撤销 Toast。

**公式：**

- 标题：动词 + 名词 + ？（「删除项目？」「发布到正式环境？」）。不写「确定要…吗」「Are you sure」（Semi Modal、M、Yifrah）。
- 正文：一句，只说后果，不重复标题（Semi）。不可逆就明说「无法恢复」。影响范围写具体：「项目下 12 个评测集会一起删除。」
- 按钮：主按钮用标题里的动词（删除），次按钮「取消」（Semi、Apple、NNg、Yifrah）。危险操作按钮用警示色，但文字本身也要说清会发生什么（GOV）。
- 极端危险的操作（删除整个空间）可要求输入名称确认（NNg）。

| ✅ | ❌ |
|---|---|
| 删除项目？ / 删除后无法恢复，项目下的评测集会一起删除。 / 删除 · 取消 | 提示 / 您确定要执行删除操作吗？此操作存在一定风险，请谨慎操作！ / 确定 · 取消 |
| Delete form?（Semi） | Are you sure you want to delete form?（Semi） |
| Remove downloaded book?（M） | Are you sure you want to remove this downloaded book? You won't be able…（M） |
| 解散群组？/ 解散后不可恢复。/ 解散（飞书桌面端的做法） | 确定 |

## 6. 空状态

**公式：** 一句话 + 一个主按钮。

- 那句话说「为什么空 / 这里会放什么」，或「做什么就不空了」；不重复标题（Semi Empty、Atl）。
- 按钮用动词 + 名词，和那句话指向同一件事（Atl）。
- 首次空（从没用过）和结果空（筛选没命中）写法不同（Yifrah）：首次空给创建入口；筛选空给「清除筛选」。
- 区分加载中、加载失败、真的空（NNg《Empty States》）。加载失败不能显示成「暂无数据」。
- 文字不依赖插画也能看懂（Arco）。
- 用户做不了什么的空（等系统生成），写清楚什么时候会有、会出现什么（Pod）。

| 场景 | ✅ | ❌ |
|---|---|---|
| 首次 | 还没有评测集 · [新建评测集] | 暂无数据 |
| 筛选 | 没有符合条件的通话 · [清除筛选] | 暂无数据，请尝试其他关键词或联系管理员 |
| 等待 | 报告生成后会显示在这里，通常 3 分钟内 | 数据正在努力加载中，请耐心等待哦～ |
| 教用法 | 给常用项目加星标，会显示在这里（NNg 示例的中文化） | 这里空空如也 |

「暂无 X」在国内产品很常见（扣子、扣子罗盘），做列表内的次要空状态可以用；做页面主空状态时补上按钮。

## 7. 报错

**公式：** 现象 + 原因（确定才写）+ 下一步。

- 说清哪一步没成，不只说「失败」（Arco、Ant）。
- 原因不确定就不编（MS、Atl）；写「没有连上服务，稍后重试」比猜错原因好。
- 下一步给最细粒度的入口：重试这一条、换一个文件、去设置页补 key。能给按钮就给按钮。
- 下一步要用户做得到：只有管理员能改的设置，普通用户看到「请管理员调大输出上限」，管理员看到「去模型设置」按钮。
- 告诉用户重试有没有用。文件损坏、格式不支持、权限不足这类，重试不会好，不给「重试」按钮（Stripe 的写法：「Retries won't succeed.」/「Retry attempts might succeed after…」）。
- 就近显示：字段错误在字段下，全局错误在页面顶部（NNg、Apple）。
- 不甩锅：不写「你输错了」「非法操作」「您多次输入错误密码，我们认为此活动可疑」（Semi、GOV、MS）。
- 不透出错误码、HTTP 状态、英文异常、接口字段名（Semi：「网页出错了，请稍后重试」好于「404 ERROR」）。需要给客服排查就放「复制错误详情」。
- 不用「哎呀 / Oops / 出了点小问题」掩饰（Apple、GOV、NNg）；不加感叹号（MC）。
- 「抱歉」只在系统自己出错且后果严重（丢数据、不能继续）时用，一个就够（MS、Semi、Ant）。
- 「请」：国内产品常见「请重试」「请先提交版本」，可以用在具体动作前；不用「请您」「烦请」，也不用「请勿」「不能」式命令（Ant、Arco）。团队定了去掉就全站去掉。
- 同一个报错高频出现，改设计而不是改措辞（Apple）。

| ✅ | ❌ |
|---|---|
| URL 不可用。可联系站点管理员帮助解决。（Semi） | 404 ERROR |
| 抱歉，无法完成发布，建议重新部署（Ant） | 抱歉，发布失败（Ant） |
| 暂不支持复制草稿版本，请先提交版本（扣子罗盘） | 操作失败 |
| Your card was declined. The customer needs to use another card.（Stripe） | Payment error |
| 文件超过 20 MB，压缩后再上传 | 上传失败！错误码 413 |
| Couldn't deposit payout · [Update bank account]（Polaris） | Invalid bank account · [Next]（Polaris） |

## 8. 状态词、标签（Tag）、徽标

- 四种形态：`待 X`（还没开始）/ `X 中`（进行中）/ `已 X`（完成）/ `X 失败`。同一流程每一步都套同一组（腾讯云智能体平台：解析中 / 解析失败 / 审核中 / 审核失败 / 学习中 / 学习失败）。
- 2–4 字；Tag 2–6 字（TD）；徽标文字 < 4 字（Arco）。
- 必要时在 tooltip 补一句这个状态意味着什么：能不能继续、要不要等。
- 不可逆的终态用更重的词区分：删除 → 回收站 → 彻底删除（飞书）；Delete → Trash → permanently delete（Notion）。

---

## 9. tooltip、帮助图标

- 只放补充信息和引导，不放报错、不放按钮和链接（Semi Tooltip）。
- 不重复可见标签（NNg）。
- 完成任务必需的信息不能只放 tooltip，它会消失（NNg）。
- 一到两句，单句不加句号（Semi）。
- 禁用状态的按钮用 tooltip 说什么时候能用：「试运行通过后可以提交」（扣子）。
- 键盘聚焦也能看到（NNg）。

---

## 10. 开关、单选、复选、设置项

- 开关文字说开启后发生什么，不加逻辑词，不写反义（TD、Apple）：「通话结束后发送短信」，不写「是否不发送挂机短信」。
- 单选 / 复选选项不加标点，平级选项用同一种词性（Semi）。
- 设置项直接链到位置，不描述「请前往设置 > 通用 > 高级…」（Apple）。

---

## 11. 引导、说明段、横幅

- 默认不要。Krug：欢迎语（happy talk）和操作说明（instructions）都该删。
- 真要写：一句说用户能得到什么，一个按钮去做。步骤型引导最多 3 步，每步一个动词。
- 横幅正文压到 1–2 句，补充标题而不是复述标题（Semi Banner / Notification）。
- 先写好处再写条件（Ant）：「为了让你的账户更安全，请设置手势密码」好于「马上设置手势密码」。

---

## 12. 后端返回给用户的提示

- 后端 `message` 就是界面文案，按报错公式写。Stripe 的 API 错误 message 明确是「human-readable…can be shown to your users」。
- 结构建议：`code`（给程序）+ `message`（给人，一句现象 + 下一步）+ `detail`（给排查，不直接展示）。
- 一个错误码对应一句人话，前端按 code 映射，不在展示处拼接英文异常。
- 涉及安全的原因不要说透（Stripe：疑似欺诈的拒付，对终端用户按普通拒付展示）。

## 13. 首屏标题、功能卡片（产品内的介绍位）

不写广告，写产品替谁做什么。

- 主标题：一句说清做什么，≤ 16 字。「从通话录音生成外呼提示词」，不写「一站式 AI 外呼智能生产平台」。
- 副标题：列 2–3 件用户真的能做的事，按使用顺序。「上传录音生成初稿，用评测集检验，通过后发布」。
- 功能卡片：标题动词 + 名词（生成提示词、评测提示词），正文一句说用户得到什么。
- 数字和效果只写有依据的；没有就留 `[待补]`，不编「效率提升 300%」。
- 不用 emoji 当图标，不用破折号连品牌名和口号。
- 英文 CTA 写点完去哪：「Upload recordings」「Create project」，不写「Get started now」「Unlock the power of AI」（NNg《"Get Started" Stops Users》）。

## 14. 数字、时间、标点（中文界面）

- 阿拉伯数字：「3 条短消息」不写「三条」（Ant）。四位以上用千分位：3,456（Ant、Arco）。
- 中文与英文、数字之间加空格：「2 个」「上传 CSV 文件」；全角标点与英文数字之间不加（Ant、Arco）。
- 日期 `2026-09-25`，时间 24 小时制 `14:30`（Semi、Ant、Arco）。时间范围 `2026-09-01 ~ 2026-09-25`。
- 相对时间：刚刚 → N 分钟前 → N 小时前 → `09-25 14:30` → `2025-09-25 14:30`（Ant）。
- 表格空值用 `--`，单位放列标题里（Ant）。
- 不加句号：按钮、标题、Toast、占位符、tooltip 单句、单选复选项、菜单、标签（Semi、Ant、M）。多句段落才用句号。
- 感叹号：界面里基本不用；报错里绝不用（MC、Ant）。
- 省略号用「…」，表示进行中（「导入中…」）或截断（Semi、Ant、Arco）。
- 用词：「其他」不写「其它」；「登录」不写「登陆」；「账号」统一一种写法（Semi、Ant）。
- 第三人称性别不明写「TA」（Arco）；不用黑名单 / 白名单，用禁用名单 / 允许名单（Semi）。
- 不用绝对词：绝不、最好、100%、永远（Semi、Ant、Arco、M）。

---

## 15. 英文界面补充

- Sentence case：按钮、标题、菜单、标签只首字母大写（Semi、M、MS、Atl、Polaris）。Apple 平台的按钮和 alert 标题用 Title Case，跟随平台。
- 用缩略式（can't, you'll），但报错和严肃信息里慎用（Semi）。GOV.UK 建议避开否定缩略式（can't, don't），怕被误读。
- 不用 e.g. / i.e. / etc.，写 for example / and more（Semi、M、Atl）。
- 用 you；少用 we（Apple 不用 we，Atlassian 报错里用 we 替用户担责——跟随产品已有口径）。
- 单句不加句号；多句加句号（M、Semi）。不用分号（Semi）。

## 交付前自检清单

**删**
- [ ] 每一段说明文字都问过「删了用户会卡住吗」
- [ ] 没有欢迎语、自夸、「本页面用于…」
- [ ] tooltip 没有重复可见标签

**写法**
- [ ] 按钮：动词开头，2–6 字，和打开的页面标题一致
- [ ] 标题：关键词在前，无句号
- [ ] 标签：名词，不是填写说明；占位符没有承载必需信息
- [ ] Toast：名词 + 动词，无句号、无感叹号、无语气词
- [ ] 确认弹窗：标题动词 + 名词 + ？，正文一句说后果，按钮用标题动词
- [ ] 空状态：一句话 + 一个按钮；区分首次空、筛选空、加载失败
- [ ] 报错：现象 + 下一步；无错误码、无英文异常、不甩锅、不编原因
- [ ] 状态词：同一流程同一组形态

**用词**
- [ ] 用的是用户行业的叫法，没有实现词和内部代号
- [ ] 同一对象、同一动作全站一个词
- [ ] 称呼统一（你 / 您二选一）
- [ ] 没有 `ai-tells.md` 里的空洞大词、假对比、铺垫收尾、翻译腔

**格式**
- [ ] 中英文、数字间有空格；数字阿拉伯化；日期时间格式统一
- [ ] 没有加粗、破折号、emoji 当装饰

**安全**
- [ ] 没动程序比较的字符串、i18n 键、提示词、人工定稿内容
- [ ] 改过的中文键在代码里 grep 过所有引用
